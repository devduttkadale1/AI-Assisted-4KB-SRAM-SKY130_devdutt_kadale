# Week 5 Task 4 — Goal B Exact 2×16 Feasibility Conclusion

## Final classification

**INFEASIBLE_IN_NORMAL_OPENRAM_FLOW**

Target:

- OpenRAM
- SKY130
- 1.8 V
- single-port SRAM
- exactly 2 logical words
- exactly 16 data bits per word
- exactly 1 logical address bit

## Evidence-based conclusion

An exact 2-word × 16-bit SRAM has only the following useful normal
organizations while retaining a one-bit logical address:

1. one bank, words_per_row=1:
   - 2 logical rows
   - 16 columns
   - 1 row-address bit

2. one bank, words_per_row=2:
   - 1 logical row
   - 32 columns
   - 1 column-address bit

3. two banks, words_per_row=1:
   - 1 logical row per bank
   - 16 columns
   - 1 bank-select bit

In the pristine OpenRAM source used for this project, the row-address
path instantiates the configured `decoder`, whose default implementation
is `hierarchical_decoder`.

The pristine hierarchical decoder does not implement the 0-input or
1-input decoder required by the exact 2×16 organizations. Its
`determine_predecodes()` implementation only defines cases beginning
at two inputs, and the physical-layout path explicitly reports that
non-hierarchical decoding for small row counts is not supported.

Adding enough spare rows to reach a supported hierarchical decoder
increases row-address width and therefore no longer preserves the exact
one-bit external interface required for a two-word memory.

No pristine SKY130 or normal configuration override was found that
provides an alternate supported tiny row decoder.

Therefore the literal 2-word × 16-bit target cannot be generated by
this OpenRAM version using the normal, unmodified SKY130 flow.

## Historical configuration findings

A historical true `num_words=2` attempt also used
`words_per_row=8`. That configuration is invalid because two total
words cannot form a valid eight-words-per-row organization; it leads
toward zero calculated logical rows.

Correcting that configuration error does not solve the problem:
`words_per_row=1` and `words_per_row=2` produce the unsupported tiny
decoder organizations described above.

Thus an earlier configuration error existed, but the final blocker is
an architectural limitation.

## Misleading historical artifacts

The archived file named `task4_sram_2x16` is not a 2-word × 16-bit
macro. Its preserved configuration and generated SPICE metadata show
16 words × 16 data bits.

Likewise, OpenRAM's golden artifact named `sram_2_16_1_sky130` is not
evidence for 2 words × 16 bits. Its generated SPICE header identifies
16 words × 2 data bits.

Neither artifact may be represented as satisfying the Week 5 literal
2-word × 16-bit requirement.

## Goal-B stop-rule decision

Per the controlled one-day Goal-B stop rule:

- do not modify OpenRAM core code;
- do not add a custom tiny decoder;
- do not modify SKY130 technology files to bypass the restriction;
- do not rename a 16×16 macro as 2×16;
- do not proceed to DRC/LVS/extraction/characterization for a substitute
  macro and call it the requested design;
- preserve the validated historical 16×16 work as historical evidence;
- preserve Week 6 Task 5 unchanged.

literal Goal-B target because no legitimate exact macro can be produced
